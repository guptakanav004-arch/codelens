# CodeLens AI — Professional AI Code Review Platform

CodeLens AI is an AI-assisted code-review platform. It runs **static analysis** on your code, sends the code and the findings to **NVIDIA Nemotron**, validates the model's structured JSON response, and shows a polished review dashboard: quality scores, issues, explanations, complexity, security findings and an optimized version you can diff and apply.

> Built as a college mini-project. The UI follows a premium developer-SaaS style (dark-first, with a light theme toggle).

## Features

- **Workspace** — IDE-style three-part layout: sidebar (new review, recent reviews, settings), Monaco editor, resizable analysis panel.
- **Monaco editor** — syntax highlighting, line numbers, 9 languages (Python, Java, C, C++, JavaScript, TypeScript, HTML, CSS, SQL), language auto-detection, upload / drag-and-drop, sample code (Python, Java, C++, JavaScript), clear, keyboard shortcut (`Ctrl/⌘ + Enter`), issue-line highlighting and click-to-navigate from issues to editor lines.
- **Real analysis pipeline** — validation → static analysis → Nemotron → Pydantic/Zod validation → merge → score reconciliation.
- **Results dashboard** — quality ring, severity chart (Recharts), per-category scores, severity tabs (All / Critical / High / Medium / Low / Info), expandable issue cards with impact, fix and code suggestion.
- **Explanation** — Beginner / Intermediate / Advanced, generated by Nemotron on demand.
- **Optimization** — diff viewer, copy, download, and *explicit* "Replace editor code" (never automatic).
- **Security** — static security tooling + AI findings + optional focused security review, with a standing disclaimer.
- **Complexity** — Radon-measured metrics (Python) clearly separated from AI Big-O *estimates*.
- **UX** — progress stages, skeleton loading, error states per failure type, empty states, toasts, copy buttons, tooltips, responsive/mobile layout, review history stored in the browser.

## Honest design choices

- Submitted code is **never executed**. It is only parsed or piped to analysis tools.
- Code is wrapped in randomised delimiters and the model is told it is *untrusted data*, not instructions.
- AI line numbers outside the file are dropped (`null`); scores are capped when serious findings exist.
- If the AI fails or is not configured, the app shows an error. It never fabricates a review.
- Loading stages are *indicative*: the backend exposes one request, so true per-stage progress is not measurable.

### A note on the frontend framework

The original brief asked for React + Vite + React Router. This repository's runtime is a Next.js project, so the same React/TypeScript component architecture is delivered with the Next.js App Router (file-based routing replaces React Router; `src/views/` holds the page components). Components are plain React and can be moved into a Vite app unchanged apart from the routing/`next/link` imports.

### Two interchangeable engines (one API contract)

The browser always calls `/api/*` on the Next.js server:

1. **`BACKEND_API_URL` set** → Next.js proxies to the Python FastAPI backend (full tooling: Ruff, Bandit, Radon, ESLint, AST).
2. **`BACKEND_API_URL` empty** → the built-in TypeScript engine (`src/lib/server`) handles the request: pattern scanner + heuristic metrics + the same Nemotron prompts and validation. Ruff/Bandit/Radon/ESLint are reported as *unavailable* in this mode.

Both return the same JSON shape (`src/types/review.ts` ⇔ `backend/app/schemas/review.py`).

## API

| Endpoint | Description |
|---|---|
| `GET /api/health` | Status, whether Nemotron is configured, tool availability |
| `POST /api/review` | `{ code, language, review_mode: full\|security\|performance\|quick }` → full structured review |
| `POST /api/explain` | `{ code, language, level: beginner\|intermediate\|advanced }` |
| `POST /api/optimize` | `{ code, language }` → `{ optimized_code, notes, summary }` |
| `POST /api/security-review` | `{ code, language }` → security-only findings + disclaimer |

Errors always look like `{ "error": { "code": "...", "message": "..." } }` (e.g. `empty_code`, `unsupported_language`, `code_too_large`, `ai_not_configured`, `ai_invalid_key`, `ai_rate_limited`, `ai_timeout`, `ai_malformed_response`, `backend_unreachable`). FastAPI docs: `http://localhost:8000/docs`.

## Installation & running

### Frontend (Next.js)

```bash
npm install
cp .env.example .env.local     # then edit
npm run dev                    # http://localhost:3000
```

With no further configuration the built-in engine is used.

### Python backend (optional but recommended)

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                  # add NVIDIA_API_KEY
uvicorn app.main:app --reload --port 8000
```

Then set `BACKEND_API_URL=http://localhost:8000` in the frontend `.env.local` and restart `npm run dev`.

Optional: install ESLint (`npm i -g eslint`) to enable JavaScript linting in the Python backend.

Run backend tests: `cd backend && pytest` (the Nemotron call is mocked).

## Environment variables

| Variable | Where | Purpose |
|---|---|---|
| `NVIDIA_API_KEY` | server only | NVIDIA API key. **Never** prefix with `NEXT_PUBLIC_`. |
| `NEMOTRON_MODEL` | server | Model id, default `nvidia/llama-3.3-nemotron-super-49b-v1.5` |
| `NVIDIA_API_BASE_URL` | server | Default `https://integrate.api.nvidia.com/v1` |
| `NEMOTRON_TIMEOUT_SECONDS`, `NEMOTRON_MAX_TOKENS` | server | Tuning |
| `BACKEND_API_URL` | Next.js server | Enables proxying to FastAPI |
| `NEXT_PUBLIC_API_BASE_URL` | browser | Optional API base URL (defaults to same origin; equivalent of `VITE_API_BASE_URL`) |

## Nemotron API configuration

1. Create a key at <https://build.nvidia.com> (API Catalog).
2. Set `NVIDIA_API_KEY`. Optionally change `NEMOTRON_MODEL` to any chat model your key can access.
3. The service calls `POST {NVIDIA_API_BASE_URL}/chat/completions` (OpenAI-compatible), strips `<think>` blocks and code fences, extracts the JSON object, repairs trailing commas, then validates with Pydantic/Zod. Rate limits (429), auth failures (401/403), timeouts, network errors and malformed responses each map to a distinct, user-friendly error.

Without a key the workspace shows an "AI configuration required" state; no fake results are produced.

## Limitations

- AI findings can be wrong or incomplete; scores and Big-O values are estimates, not verified measurements.
- Static-analysis depth varies by language: Python is deepest; TypeScript has no ESLint run (needs `@typescript-eslint/parser`); other languages use pattern scanning + AI.
- Optimized code is not compiled or tested.
- Security findings are automated suggestions and do not replace a professional security audit.
- Review history is stored in the browser's `localStorage`; there is no authentication or database in this version.
- Monaco loads from a CDN by default; if blocked, a plain-text fallback editor is used.
